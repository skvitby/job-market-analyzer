# Чек-лист публикации job-market-analyzer

Проходи пункты по порядку, команды — в bash из корня проекта. В конце покажи пользователю таблицу «пункт — результат — что исправить». Сам ничего не исправляй и не публикуй без подтверждения; исправления — по одному.

## 1. Секреты и личные данные

```bash
# В индексе нет личных и генерируемых файлов (вывод должен быть пустым)
git ls-files | grep -E '^\.env$|my_cv|^data/[^.]|^reports/.*\.md$|^tmp/|^\.obsidian/'

# Игнор работает
git check-ignore .env profile/my_cv.md   # должны быть выведены оба пути

# Нет ключей в отслеживаемых файлах и в подготовленных изменениях (вывод должен быть пустым)
git grep -nE 'sk-ant-[A-Za-z0-9_-]{10,}|sk-[A-Za-z0-9]{20,}|HH_APP_TOKEN=[A-Za-z0-9]{10,}|HH_CLIENT_SECRET=[A-Za-z0-9]{10,}'
git diff --cached | grep -nE 'sk-ant-|sk-[A-Za-z0-9]{20,}'

# Нет ключей в истории (вывод должен быть пустым)
git log -p --all | grep -nE 'sk-ant-[A-Za-z0-9_-]{10,}' | head
```

Если ключ найден в истории — не переписывай историю сам: сообщи пользователю, что ключ нужно отозвать у провайдера, и обсуди дальнейшие шаги.

Отдельно просмотри глазами изменённые `.md` под git: нет ли фрагментов резюме, e-mail, телефона, названий работодателей из личного опыта сверх уже опубликованного.

## 2. Код

Бесплатные проверки из раздела 4 `SKILL.md` проходят без ошибок. `requirements.txt` содержит все импортируемые сторонние пакеты.

## 3. Ссылки в документации

```bash
.venv/Scripts/python.exe -X utf8 - <<'EOF'
import re, pathlib, urllib.parse
bad = []
for md in pathlib.Path('.').glob('**/*.md'):
    if any(p in md.parts for p in ('.venv', 'data', 'reports', 'tmp', '.claude', '.obsidian')):
        continue
    for link in re.findall(r'\]\(([^)\s]+)\)', md.read_text(encoding='utf-8')):
        if link.startswith(('http', '#', 'mailto:')):
            continue
        target = (md.parent / urllib.parse.unquote(link.split('#')[0])).resolve()
        if not target.exists():
            bad.append(f'{md}: {link}')
print('\n'.join(bad) or 'OK: битых ссылок нет')
EOF
```

Ссылки на файлы, которых нет в git (например, `reports/...`), на GitHub будут битыми — допустимы только в `docs/STATUS.md` с пометкой «не в git».

## 4. Актуальность документов

- `docs/STATUS.md`: дата обновления, последний коммит, «Следующий шаг» соответствуют текущему состоянию.
- `README.md`: статус US, цифры результатов и список артефактов совпадают со `STATUS.md` и протоколами; новые документы добавлены в таблицу артефактов.
- Руководство пользователя отражает текущие команды и параметры (сверить с `<команда> --help`).
- Отложенное за сессию записано в бэклог `requirements.md`.

## 5. Git

```bash
git status --short
git remote -v
git log origin/main..HEAD --oneline   # что уйдёт при push
```

Рабочее дерево чистое или все изменения осознанно в коммите; сообщения коммитов на английском, по одному на шаг. После подтверждения пользователя — `git push`.

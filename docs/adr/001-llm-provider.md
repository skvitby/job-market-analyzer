# ADR-001: Выбор LLM-провайдера для анализа вакансий и работы с резюме

**Статус:** Принято
**Дата:** 24.09.2026
**Связанные требования:** US-03 (AC 3.1, AC 3.3), US-04, US-05, AC 1.5, NFR-2, открытый вопрос №3

## 1. Контекст

Проект использует LLM в двух типах задач с разными требованиями:

| Задача | Где используется | Какие данные уходят в модель | Объём |
|---|---|---|---|
| **Анализ вакансий** — выявление навыков, не покрытых словарём | US-03, AC 3.1 | Публичные тексты вакансий с HH | Сотни–тысячи запросов: ~900 вакансий при первой загрузке, ~1 800 новых в месяц |
| **Работа с резюме** — сопоставление с рынком, сопроводительные письма, советы по CV | AC 3.3, US-04, US-05 | Резюме пользователя (персональные данные) + вакансия | Единичные запросы |

Исходно в ТЗ зафиксирован стек Claude API (Anthropic SDK). При проектировании US-03 встал вопрос стоимости массовой обработки вакансий и наличия более дешёвых или бесплатных альтернатив.

**Оценка нагрузки на одну вакансию:** ~900 input-токенов (полное описание ~2 000 символов + доля инструкции) и ~100 output-токенов (список навыков в JSON). Токенизаторы у моделей разные, поэтому расчёты ниже приблизительные.

**Ограничения среды:**
- Пользователь находится в регионе РФ/РБ и работает через VPN (Mullvad); часть зарубежных сервисов доступна только через VPN, часть российских сервисов блокирует VPN-адреса (как HH).
- Резюме — персональные данные, их обработка третьими сторонами нежелательна.
- Проект — портфолио BA/SA: важны прозрачность решений и соответствие ТЗ.

## 2. Критерии выбора

1. **Стоимость** — на объёме проекта (сотни–тысячи вакансий).
2. **Качество** — извлечение навыков из русскоязычного текста, стабильный JSON-ответ.
3. **Приватность** — где и как обрабатываются данные, особенно резюме.
4. **Доступность** — работа из РФ/РБ, через VPN или без него.
5. **Стабильность условий** — предсказуемость цен и лимитов.
6. **Сложность интеграции** — объём кода и поддержки.
7. **Соответствие ТЗ** — исходный стек Claude API.

## 3. Рассмотренные варианты

### 3.1. Claude (Anthropic) — платно

Цены на июнь 2026, $ за 1 млн токенов:

| Модель | Input | Output | Назначение |
|---|---|---|---|
| **Haiku 4.5** | 1,00 | 5,00 | Простые массовые задачи: извлечение, классификация |
| **Sonnet 5** | 2,00 | 10,00 | Баланс качества и цены |
| **Opus 5** | 5,00 | 25,00 | Сложные задачи |

| Fable 5.1 | 10,00 | 50,00 | Максимальное качество, для задачи избыточна |

Скидки: **Batch API −50%** (асинхронная обработка до 24 ч); **prompt caching** — повторяющийся префикс ~10% цены, но наш префикс (~800 токенов), вероятно, ниже минимального порога кэширования. Оплата — предоплатой в Anthropic Console, отдельно от подписки Claude.

Оценка затрат:

| 48 вакансий (Минск) | ~$0,07 | ~$0,03 | ~$0,13 | ~$0,33 |
| ~890 вакансий | ~$1,25 | ~$0,60 | ~$2,50 | ~$6 |
| Поток за месяц (~1 800) | ~$2,50 | ~$1,25 | ~$5 | ~$12 |

- ➕ Высокое качество, гарантированный JSON (structured outputs), стабильные цены, соответствует ТЗ.
- ➖ Самый дорогой из платных вариантов; доступ из РФ/РБ — через VPN.

| **DeepSeek V4.1 Flash** (off-peak / peak) | 0,15 / 0,30 | 0,60 / 1,20 | ~$0,17 / $0,35 | ~$0,35 / $0,70 | в 4–7 раз |

- ➕ В 4–8 раз дешевле; хорошо работают с русским языком и JSON; OpenAI-совместимый API; возможно, доступны из РФ/РБ без VPN (требует проверки).
- ➖ **Абсолютная экономия мала** — ~$1–2 в месяц на объёме проекта; второй провайдер — это код, тесты и поддержка.
- ➖ **Нестабильные условия** — DeepSeek несколько раз менял цены в 2026, ввёл пиковые часы; у Qwen-Plus промо-цена.
- ➖ **Юрисдикция данных** — DeepSeek (Китай), Qwen (Сингапур): приемлемо для публичных вакансий, нежелательно для резюме.
- ➖ Оплата — нужна карта, принимаемая зарубежным сервисом (как и у Anthropic).

### 3.3. Бесплатные облачные тарифы

| Вариант | Качество vs Haiku | Бесплатный лимит | Ограничения |
|---|---|---|---|
| **Google Gemini Flash** (AI Studio) | Сопоставимо | 50 запросов/день, 20/мин (~500 вакансий/день пакетами по 10) | Данные free-тарифа могут использоваться для обучения; из РФ/РБ — через VPN |
| **Groq** (gpt-oss, Qwen) | Сопоставимо | ~1 000 запросов/день, 30/мин | Состав бесплатных моделей меняется (Llama убрали в августе 2026); через VPN |
| **OpenRouter** (`:free`) | Зависит от модели | 50 запросов/день | Малые лимиты, модели могут исчезать |
| **GigaChat** (Сбер) | Чуть ниже, сильный русский | Freemium: от 1 млн токенов/год (документация противоречива: 1 млн vs 365 млн) | Sber ID, сертификат НУЦ Минцифры, вероятно, блокирует VPN |

- ➕ Бесплатно.
- ➖ Лимиты и условия меняются без предупреждения; **резюме нельзя отправлять** в тарифы, где данные идут на обучение.

### 3.4. Локальная модель через Ollama

Железо пользователя: GTX 1650 Ti (4 ГБ VRAM), 16 ГБ RAM, Ollama установлена.

| Модель | Работа на железе | Качество vs Haiku |
|---|---|---|
| `qwen3:4b` (выбрана instruct-версия `qwen3:4b-instruct-2507-q4_K_M`, см. раздел 6) | Целиком в видеопамяти, быстро | Заметно ниже на русском |
| `qwen3:8b` | Частично на CPU: ~десятки секунд на вакансию, несколько часов на весь рынок | Ниже, но приемлемо |

- ➕ Бесплатно, без лимитов, **данные не покидают компьютер** — лучший вариант по приватности для резюме.
- ➖ Качество и скорость ниже облачных моделей.

## 4. Решение

Сделать LLM-провайдера **настраиваемым отдельно для каждого типа задач** через `llm_preferences.llm_providers` в `profile/preferences.json` (AC 1.5):

```json
"llm_providers": {
  "vacancy_analysis": {"provider": "anthropic", "model": "claude-haiku-4-5"},
  "cv_processing":    {"provider": "anthropic", "model": "claude-haiku-4-5"}
}
```

| `provider` | Клиент | Ключ в `.env` | Адрес по умолчанию |
|---|---|---|---|
| `anthropic` (**по умолчанию**) | Anthropic SDK | `ANTHROPIC_API_KEY` | — |
| `deepseek` | OpenAI-совместимый | `DEEPSEEK_API_KEY` | `https://api.deepseek.com` |
| `qwen` | OpenAI-совместимый | `DASHSCOPE_API_KEY` | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1` |
| `ollama` | OpenAI-совместимый | не нужен | `http://localhost:11434/v1` |

Адрес можно переопределить параметром `base_url`.

**По умолчанию** обе задачи используют **Claude Haiku 4.5**: соответствует ТЗ, качество с запасом, стоимость — центы–единицы долларов в месяц.

**Рекомендуемая альтернативная конфигурация** (для экономии и приватности):
- `vacancy_analysis` → дешёвая модель (DeepSeek V4.1 Flash / Qwen-Flash) — публичные данные, массовые запросы;
- `cv_processing` → Claude или локальная модель в Ollama — персональные данные остаются у проверенного провайдера или на компьютере пользователя.

Бесплатные облачные тарифы (Gemini, Groq, OpenRouter) технически подключаются через тот же OpenAI-совместимый клиент с `base_url`, но **не рекомендуются для `cv_processing`**.

## 5. Последствия

**Положительные**
- Провайдера можно сменить без изменения кода — достаточно правки `preferences.json` и ключа в `.env`.
- Массовую обработку вакансий можно удешевить в 4–8 раз, не жертвуя приватностью резюме.
- Возможна полностью бесплатная и офлайн-работа через Ollama.

**Отрицательные и риски**
- Два клиента (Anthropic SDK и OpenAI-совместимый) — больше кода и тестов; добавляется зависимость `openai`.
- Качество ответов разных моделей различается: результаты анализа, полученные разными моделями, не полностью сопоставимы. Поэтому в кэше LLM-результатов фиксируется модель, обработавшая вакансию.
- Цены альтернативных провайдеров нестабильны — таблицы в этом ADR актуальны на дату решения и требуют периодической сверки.
- Structured outputs Anthropic гарантируют JSON по схеме; у OpenAI-совместимых провайдеров используется JSON-режим, ответ нужно дополнительно валидировать.

**Когда пересмотреть решение**
- Объём вырастет до десятков тысяч вакансий — тогда экономия от дешёвых моделей и Batch API станет существенной.
- Anthropic станет недоступен из региона пользователя или изменит цены.
- Локальное железо позволит запускать модели уровня 14B+ с приемлемой скоростью.

## 6. Результаты проверки (24.09.2026)

Проверка реализации `llm_service.py` (шаг 9): один и тот же фрагмент требований вакансии с 11 навыками (системный анализ, SQL, PostgreSQL, REST API, Swagger, Kafka, Jira, Confluence, BPMN, UML, Camunda), инструкция «извлеки хард-скилы, верни JSON».

| | Claude Haiku 4.5 | Qwen3 4B instruct (Ollama) | Gemma 4 E2B (Ollama) |
|---|---|---|---|
| Найдено навыков | 11 из 11 | 11 из 11 | 10 из 10 (в тесте без Camunda) |
| Время ответа (модель загружена) | 3,7 с | 5,4 с | 9,6 с |
| Первый запрос (загрузка модели в память) | — | 71 с | 120 с |
| Стабильность при повторе | — | Одинаковый ответ | Разные формулировки |
| Стиль названий | Короткие: `BPMN`, `REST API` | Длиннее: `моделирование BPMN`, `проектирование REST API` | Нестабильный |
| Скрытые «размышления» | Нет | Нет | ~80% сгенерированных токенов |
| Стоимость запроса | ~$0,0006 | Бесплатно | Бесплатно |

**Выбор локальной модели.** Скачана `qwen3:4b-instruct-2507-q4_K_M` из официальной библиотеки Ollama (2,5 ГБ, Apache 2.0, sha256 сверен); Gemma 4 E2B удалена. Причины:
- **Instruct-версия, а не thinking:** извлечение навыков — задача на распознавание, а не на рассуждение; «размышления» замедляют ответ в разы, расходуют контекст (у Ollama по умолчанию 4 096 токенов) и повышают риск отклонения от JSON-формата. Сравнение с `qwen3:4b-thinking-2507` на спорных вакансиях (CRM как домен или навык, должность или опыт) — опционально, на шаге 10.
- **Qwen3 4B, а не Qwen3.5 4B:** Qwen3.5 4B мультимодальная (3,4 ГБ) — поддержка изображений проекту не нужна, а модель не помещается целиком в 4 ГБ видеопамяти.

**Выявленные особенности, учитываемые дальше:**
- Контекст Ollama 4 096 токенов → для провайдера `ollama` изначально задан `batch_size = 2` вакансии на запрос (у облачных — 10); уточнено до 1 по итогам сравнения ниже.
- Разные модели по-разному называют один навык → на шаге 10 ответы LLM нормализуются: инструкция требует коротких канонических названий, результат сопоставляется со словарём синонимов.

### 6.1. Сравнение на реальных вакансиях (48 вакансий Минска, шаг 10)

Задача `vacancy_analysis`: извлечение навыков из полных описаний, навыки из словаря отсекаются, остаток — раздел «Навыки вне словаря, найденные LLM».

| | Claude Haiku 4.5 | Qwen3 4B instruct (Ollama) |
|---|---|---|
| Размер пакета | 10 вакансий | 2 вакансии |
| Обработано вакансий | **48 из 48** | **36 из 48** — в половине пакетов модель вернула результат только по одной вакансии |
| Время | **58 с** (5 запросов) | ~11 мин (24 запроса) |
| Токены / стоимость | 44 354 вход + 4 313 выход ≈ **$0,066** | Бесплатно |
| Навыков на вакансию (всего / вне словаря) | 13,9 / 6,8 | 14,2 / 7,6 |
| Совпадение наборов навыков (Jaccard, 36 общих вакансий) | 0,42 | 0,42 |

**Наблюдения:**
- Низкое совпадение (0,42) вызвано в основном **разными формулировками** одного навыка (`HTTP` / `HTTP-запросы`, `СУБД` / `Реляционные БД`), а не разным смыслом.
- **Haiku сильнее в предметных знаниях:** в банковской вакансии выделила пруденциальную и управленческую отчётность, банковский домен; Qwen — общее «данные».
- **Qwen местами полнее в практиках аналитика:** в вакансии 137704093 нашла «Сбор требований» и «Критерии приёмки», которые Haiku пропустила.
- **Общие недостатки обеих моделей:** синонимы попадают в отдельные строки (`Word` / `MS Word`, `Acceptance Criteria` / `Критерии приёмки`, `Микросервисы` / `Микросервисная архитектура`), встречаются слишком общие пункты («Разработка ПО», «Документация»). Решение — пополнять словарь частыми находками LLM с синонимами: тогда они переходят в точный поиск.
- Пропуски у Qwen **не связаны с контекстом**: максимальный запрос — 2 572 токена из 4 096. Причина — слабое следование инструкции малой моделью при нескольких вакансиях в запросе.

**Вывод:** решение раздела 4 подтверждено — для `vacancy_analysis` по умолчанию Claude Haiku 4.5 (полнота 100%, в 11 раз быстрее, стоимость — центы). Qwen3 4B — бесплатный резервный вариант; для `ollama` по умолчанию установлен **`batch_size = 1`**.

### 6.2. Контекстное окно Ollama

Ollama по умолчанию ограничивает контекст 4 096 токенами (модель Qwen3 4B поддерживает до 256K). Способы расширить:

| Способ | Как | Применимость в проекте |
|---|---|---|
| Глобально | Ollama → Settings → Context length, или переменная окружения `OLLAMA_CONTEXT_LENGTH=8192` + перезапуск | Затрагивает все модели |
| Для одной модели (**рекомендуется**) | Modelfile: `FROM qwen3:4b-instruct-2507-q4_K_M` + `PARAMETER num_ctx 8192`, затем `ollama create qwen3-4b-8k -f Modelfile`; в `preferences.json` — `"model": "qwen3-4b-8k"` | Отдельный вариант модели, без дублирования файлов на диске |
| В запросе (`options.num_ctx`) | Только через нативный API `/api/chat` | Не подходит: проект использует OpenAI-совместимый адрес `/v1` |

Цена расширения на железе пользователя (4 ГБ VRAM) — память под KV-кэш, ~144 КБ на токен для Qwen3 4B:

| Контекст | KV-кэш | Последствия |
|---|---|---|
| 4K (по умолчанию) | ~0,6 ГБ | Уже ~1/3 модели работает на CPU |
| 8K | ~1,2 ГБ | Больше на CPU, заметное замедление |
| 16K | ~2,4 ГБ | Значительная часть на CPU, медленно |
| 32K | ~4,7 ГБ | Только RAM, очень медленно |

Смягчение: сжатие KV-кэша — `OLLAMA_FLASH_ATTENTION=1` и `OLLAMA_KV_CACHE_TYPE=q8_0` (примерно вдвое меньше памяти при минимальной потере качества).

**Решение:**
- Для `vacancy_analysis` контекст **не расширяется**: запросы с одной вакансией укладываются в 4K, а увеличение пакетов ухудшает полноту у малой модели.
- Для `cv_processing` расширение **обязательно**, если выбрана Ollama: резюме (~1–2K токенов) + полная вакансия (~1,5K) + инструкция + развёрнутый ответ превышают 4K, а Ollama при переполнении **молча обрезает** начало запроса вместе с инструкцией. Вариант модели с `num_ctx 8192` через Modelfile создаётся при реализации US-04.

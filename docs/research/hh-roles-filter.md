# Роли HH и фильтр вакансий не из IT

Исследование к пункту 26 бэклога ([requirements.md](../../requirements.md), раздел 9), связанный пункт — 27. Решение по фильтру ещё не принято, открытые вопросы перечислены в конце.

## Проблема

`fetch` находит вакансии, которые к IT не относятся. На 02.10.2026 в Минске таких было 4 из 68: три «Кредитный аналитик» и «Бизнес-аналитик (экономическая сфера)». Они попадают в `analyze` и искажают частоты навыков и покрытие рынка резюме.

## Что такое роль HH

- **Роль HH (профессиональная роль)** — значение из справочника hh, которое работодатель выбирает при публикации вакансии. У вакансии может быть одна или несколько ролей.
- Справочник: `GET /professional_roles`.
- В выдаче поиска `GET /vacancies` роли приходят в поле `professional_roles` (список `{id, name}`).
- В поиске роль можно передать параметром `professional_role` (его можно повторять).
- Роль выбирает работодатель, а не hh, поэтому она тоже может быть указана неточно. Но с ней ошибок меньше, чем с поиском по словам названия.

Роли, которые встретились в исследовании:

| ID | Роль | Для нас |
|---|---|---|
| 150 | Бизнес-аналитик | профильная |
| 148 | Системный аналитик | профильная |
| 156 | BI-аналитик, аналитик данных | спорная (открытый вопрос 1) |
| 57 | Кредитный специалист | не IT |
| 142 | Экономист | не IT |

## Как сейчас работает поиск

`fetch` строит один запрос из `target_roles` (`src/hh_client.py`, функция `build_search_params`):

- поиск только по названию вакансии (`search_field=name`);
- роли объединяются через `OR`, каждая в скобках и без кавычек: `(Бизнес-аналитик) OR (Системный аналитик) OR …`;
- слова из `exclude_words` исключаются через `NOT` (сейчас `NOT 1С`);
- роль HH не передаётся в запрос и не сохраняется в выгрузке.

Без кавычек hh ищет каждое слово фразы отдельно: `(Бизнес-аналитик)` означает «*бизнес* и *аналитик* в любом месте названия». Поэтому:

- «Кредитный аналитик (средний **бизнес**)» — оба слова есть, вакансия проходит;
- «**Бизнес-аналитик** (экономическая сфера)» — фраза совпала целиком, вакансия проходит, хотя роль у неё 142 «Экономист».

## Проверка 07.10.2026: помогут ли кавычки

Сравнили два варианта текущего запроса по Беларуси (все 11 ролей из `target_roles`, `NOT 1С`, без фильтров по опыту и графику, за всё время, поэтому цифры больше, чем в выгрузках):

| Вариант | Вакансий |
|---|---|
| Без кавычек (как сейчас): `(Бизнес-аналитик) OR …` | 111 |
| В кавычках (точная фраза): `"Бизнес-аналитик" OR …` | 107 |

Кавычки отсеивают 4 вакансии:

| ID | Название | Роль HH | Потеря? |
|---|---|---|---|
| 133960724 | Кредитный аналитик (крупный корпоративный бизнес) | Кредитный специалист | нет |
| 134544001 | Кредитный аналитик по микро- и малому бизнесу | Кредитный специалист | нет |
| 137782516 | Аналитик отдела развития продуктов корпоративного бизнеса | Менеджер продукта | скорее нет |
| 137103627 | Ведущий специалист по AI-аналитике и оптимизации бизнес-процессов | Бизнес-аналитик (150) | **да, спорная** |

Отдельно по роли «Бизнес-аналитик»: без кавычек — 80 вакансий, из них 3 «Кредитный аналитик»; в кавычках — 76, «Кредитный аналитик (средний бизнес)» (ВТБ 138013716) всё равно находится. Почему hh считает её совпадением с точной фразой, по ответу API не понять. `IT-аналитик` не находит ничего ни в одном варианте.

Выводы:

- Кавычки убирают 2 из 3 «Кредитных аналитиков», но не все, и теряют одну подходящую вакансию (137103627).
- Вакансию с ролью «Экономист» кавычки не отсекут: её название содержит «Бизнес-аналитик» целиком.
- **Без фильтра по ролям HH не обойтись**, кавычки — в лучшем случае дополнительная мера.

## Как будет работать фильтр (предложение)

1. **Настройка.** В `search_settings` (`profile/preferences.json`) добавляется список `professional_roles` — ID ролей HH, например `[150, 148]`. Пустой список или отсутствие ключа — без фильтра, поведение как сейчас.
2. **Сбор (`fetch`).** Поиск по названию остаётся. Роли передаются в запрос параметром `professional_role` — вакансия попадает в выгрузку, только если совпали и название, и роль (пересечение). Роли вакансии сохраняются в выгрузке.
3. **Анализ (`analyze`).** Вакансии с известной ролью вне списка исключаются из анализа; число исключённых показывается в отчёте. Вакансии без сохранённой роли (старые выгрузки) — см. открытый вопрос 2.
4. **Изменение настройки.** Список ролей меняется в `preferences.json` и применяется к следующему запуску; повторная выгрузка не нужна, если роли уже сохранены.

Затрагивает US-01 (настройка), US-02 (запрос и выгрузка), US-03 (исключение и отчёт).

## Открытые вопросы

1. **Включать ли роль 156** «BI-аналитик, аналитик данных». Из 3 вакансий к профилю ближе только «Системный аналитик DWH» (136640582), две другие — аналитика данных.
2. **Что делать со старыми выгрузками** — ролей в них нет:
   - **(а)** `fetch` один раз дозапрашивает роли у вакансий текущих регионов (Беларусь — около 70 запросов, ~4 мин), `analyze` исключает вакансии с ролью вне списка — отчёт чистый сразу;
   - **(б)** старые выгрузки не трогать, их со временем вытеснит `--days`; пока они в окне анализа, мусорные вакансии остаются в отчёте.
3. **Кавычки в запросе** — переходить ли на точную фразу в дополнение к фильтру ролей. Плюс — меньше мусора на входе; минус — риск потерять подходящие вакансии (137103627).
4. **Пропуски поиска (п. 27)** — названия с `#` и «Fullstack analyst»; удобно решать вместе с фильтром.

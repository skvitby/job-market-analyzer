# Бриф: кликабельный прототип веб-интерфейса

## Продукт и аудитория

- **Продукт:** job-market-analyzer — инструмент соискателя на позицию бизнес/системного аналитика. Сейчас это CLI (см. [README](../../README.md), [требования](../../requirements.md)); прототип — первый шаг к веб-интерфейсу.
- **Пользователь:** один человек — сам соискатель (аналитик, IT-грамотный). Работает с инструментом регулярно: собрать вакансии → посмотреть рынок и пробелы → по выбранной вакансии получить письмо и советы по резюме.
- **Главная задача интерфейса:** быстро понять, что рынок просит и чего не хватает в резюме, и подготовить отклик на конкретную вакансию, не приписав себе лишнего.
- **Второе назначение:** проект в портфолио — прототип показывают работодателю.

## Объём

Вариант «б»: интерфейс не только показывает данные, но и **запускает команды** (`fetch`, `analyze`, `cover-letter`, `cv-tips`). В прототипе запуск имитируется: состояния «идёт выполнение» (с прогрессом/логом), «готово», «ошибка» — без реальных вызовов.

| 1 | **Обзор рынка** | KPI: вакансий, период публикации, покрытие рынка резюме, число пробелов; рейтинг навыков горизонтальными барами с %; фильтры региона и периода; кнопка «Обновить анализ» | `analyze` | Levels.fyi (главная метрика наверху), Habr Карьера (фильтры-«таблетки» с числами, «по N вакансиям»), Stack Overflow Survey (бары с %, вкладки) |

## Стиль

- **Деловой, сдержанный, нейтральный** — как Levels.fyi и Tremor: высокая плотность информации без перегруза, данные важнее декора.
- Эксперименты со стилем не нужны; «смелость» — максимум в одном элементе (например, в подаче рейтинга навыков или покрытия резюме).
- Светлая и тёмная тема.
- Интерфейс на русском.

## Данные

- Цифры рынка — **реальные**, из `reports/market_skills_summary.md` (Минск, 59 вакансий, топ: BPMN 69%, API 59%, SQL 56%, UML 54%, интеграции 53%; покрытие 60%).
- Цитаты из резюме, тексты писем и советов — **демо-текст**: резюме не в git, личные данные в прототип не попадают.
- Вакансии — можно реальные названия и работодатели из выгрузок (публичные данные hh).

## Технические условия

- Один файл `docs/prototype/index.html`, открывается двойным кликом, без сборки и сервера.
- Без внешних JS-библиотек; шрифты — системные или Google Fonts.
- Адаптивность до мобильного, видимый фокус клавиатуры.

## Порядок работы

1. Прочитать этот бриф и `reports/market_skills_summary.md`.
2. Показать дизайн-план (палитра, шрифты, раскладка экранов ASCII-схемами) — **ждать одобрения**.
3. Сделать прототип, показать, обсудить правки.
4. Коммит — после одобрения пользователя.
5. Затем отдельно: US-06 в `requirements.md`.

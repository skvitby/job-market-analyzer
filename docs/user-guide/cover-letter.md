# Сопроводительное письмо (`cover-letter`)

[← к оглавлению](index.md)

## Зачем

Получить за полминуты **черновик** сопроводительного письма под конкретную вакансию: 2–3 пункта, где задача вакансии прямо подтверждается опытом из резюме, без пересказа резюме и без штампов. Письмо — отправная точка: его нужно вычитать (см. «Как вычитывать письмо»).

## Запуск

**Синтаксис:**

```
.venv\Scripts\python.exe -m src.cli cover-letter <vacancy_id>
```

- `<vacancy_id>` — ID вакансии, число из ссылки `hh.ru/vacancy/<ID>`.

Нужен файл резюме `profile/my_cv.md`.

**Пример:**

```powershell
.venv\Scripts\python.exe -m src.cli cover-letter 137587921
```

Через `!` в Claude Code: `! .venv/Scripts/python.exe -m src.cli cover-letter 137587921`.

## Как получается письмо

```
вакансия: описание из data/details/ + метаданные из data/raw_vacancies_*.json
          (нет в кэше → запрос к HH, описание сохраняется в кэш)
   + profile/my_cv.md + настройки письма из preferences.json
   ↓
LLM (cv_processing), три шага по промпту prompts/cover_letter.md:
   1) пары «требование вакансии ↔ дословная цитата из резюме» (2–3)
   2) требования вакансии без подтверждения в резюме (до 10)
   3) текст письма — только на основе пар из шага 1
   ↓
код проверяет цитаты по резюме и сверяет «без подтверждения» со словарём навыков
   ↓
reports/cover_letters/cl_{ID}.md
```

- **Вакансию не обязательно выгружать заранее**: если её нет в кэше, она запрашивается у HH по ID (нужны переменные HH в `.env` и `curl` вне VPN).
- **Язык** — по `cover_letter_language`: `ru`, `en` или `auto` (английский, если в описании вакансии латинских букв больше, чем кириллических). Определённый язык пишется в метаданные файла.
- **Тон, акценты, объём** — `tone`, `focus_areas`, `cover_letter_max_words` ([Настройки](configuration.md), раздел 4.2).

## Версии

Файлы не перезаписываются — вы могли их править. Повторный запуск по той же вакансии создаёт `cl_{ID}_v2.md`, `cl_{ID}_v3.md` и т.д.; номер — наибольший существующий + 1. В терминале: `Готово: письмо → reports\cover_letters\cl_137587921_v2.md (версия 2, предыдущие не изменены)`.

Повторная генерация — нормальный способ получить другой вариант: ответы модели от запуска к запуску заметно различаются.

## Что в файле, сверху вниз

### 1. Метаданные

Frontmatter — блок свойств в начале файла между строками `---` (в Obsidian отображается как «Свойства»): `vacancy_id`, название, работодатель, город, ссылка, номер версии, дата, модель, язык, число слов. Под заголовком — строка со ссылкой на вакансию, версией и числом слов.

### 2. Текст письма

Обычный текст без Markdown — копируется в отклик на hh.ru как есть. Без подписи и заглушек вида `[Имя]`, `[Компания]`: письмо заканчивается предложением обсудить детали.

### 3. «Требования вакансии без подтверждения в резюме» (жёлтый блок)

Есть, только если модель нашла такие требования. В письме они намеренно **не упоминаются** — ни прямо, ни намёками.

- Опыт на самом деле есть, просто не описан → дописать его в резюме своими словами.
- Опыта нет → подготовиться к вопросу на собеседовании, внести в план обучения.
- Пометка **«⚠️ возможно, есть в резюме: <навык> — «фрагмент»»** — навык из пункта найден в резюме точным поиском по словарю. Модель, скорее всего, ошиблась, и пункт можно пропустить. Проверяются только навыки словаря; смысловые совпадения вне словаря («демо», «устранение ошибок») не ловятся.

### 4. «Перед отправкой» (чек-лист)

Четыре пункта ручной проверки, отмечаются галочками прямо в Obsidian:

- [ ] Все утверждения подтверждаются резюме (см. «На чём построено письмо»)
- [ ] Сроки и числа не завышены
- [ ] Язык и тон подходят вакансии
- [ ] Фразы читаются естественно

### 5. «На чём построено письмо» (свёрнутый блок)

Таблица пар «требование вакансии ↔ цитата из резюме»:

| Отметка | Значит |
|---|---|
| ✅ | Цитата найдена в резюме — пункт письма опирается на реальный фрагмент |
| ⚠️ | Цитата не найдена: модель пересказала или склеила текст. Утверждения письма по этому пункту проверить обязательно |

Если пар нет — «Прямых подтверждений требований вакансии в резюме не найдено», письмо короткое, без пунктов соответствия.

## Сообщения в терминале

| Сообщение | Что значит |
|---|---|
| `Внимание: Цитаты не найдены в резюме: N из M — пары отмечены ⚠️ …` | Часть пар не подтверждена — смотрите блок «На чём построено письмо» |
| `Внимание: Требований вакансии без подтверждения в резюме: N (из них K, возможно, есть в резюме) — см. файл письма` | Сколько пунктов в жёлтом блоке и сколько из них, вероятно, ложные |
| `Внимание: Резюме не подтверждает ни одного требования вакансии — проверьте, стоит ли откликаться` | Сигнал, что вакансия вам, скорее всего, не подходит |
| `Внимание: Письмо длиннее ориентира: N слов при cover_letter_max_words = 250` | Превышение ориентира больше чем на 20%; письмо сохранено, сократите вручную или сгенерируйте заново |

## Как вычитывать письмо

Код проверяет только то, что можно проверить механически: цитаты в таблице и ложные «без подтверждения». **Искажения возникают между цитатой и фразой письма** — таблица может быть вся в ✅, а текст всё равно приукрашен. Это ловит только вычитка.

Правила, по которым проверять (AC 4.3):

| Правило | Как нарушает Haiku 4.5 (из [протокола приёмки](../testing/test-report-us04.md)) |
|---|---|
| Каждое утверждение подтверждено резюме; совпадение только по теме не считается | «Опыт интеграций **и API** я применял на практике» — слова API в резюме нет; «**уверенным** владением SQL» при «запросы к БД (SQL)» для локализации инцидентов; «Build dashboards» натянуто на ускорение построения отчётов |
| Требования без подтверждения не упоминаются, в том числе намёками | «I am eager to expand my analytics toolkit» при Power BI и Tableau в списке без подтверждения |
| Стаж и сроки не завышены: округление только вниз («более 6 лет» при 6 годах 4 месяцах) или с оговоркой («почти 12 лет»); стаж относится только к своей роли и месту работы | «За 11 лет я участвовал в разработке…» при общем стаже 11 лет 11 месяцев; «more than 11 years as a business analyst» — общий стаж выдан за стаж в бизнес-анализе |
| Результаты (проценты, «в N раз», «с … до …») — как в резюме | Отдельно в протоколе не отмечено, но числа проверяйте всегда |
| Нет фраз из стоп-листа и штампов, текст грамматически правильный | «накопил значительный опыт», «Откликаюсь на вакансию» в начале, «Мой опыт покрывает ключевые аспекты должности», «Эта роль привлекает мне», «проводил грумингов» |

**Порядок вычитки:**

1. Раскрыть «На чём построено письмо». Пары с ⚠️ — сразу сверить с резюме.
2. Прочитать письмо **по предложению**: для каждого найти опору в таблице или в резюме. Всё, что сильнее цитаты («уверенно», «проектировал», «для анализа», «data-driven»), — убрать или ослабить до формулировки резюме.
3. Найти в тексте все числа и сроки и сверить с резюме: особенно стаж — к какой роли он относится.
4. Сверить письмо с жёлтым блоком: нет ли намёков на пункты оттуда («знаком с принципами», «быстро освою»).
5. Прочитать вслух — грамматика, штампы, естественность.
6. Отметить чек-лист «Перед отправкой».

> [!important] Главное правило
> В отклик уходит только то, что вы сможете подтвердить на интервью.

## Когда переключать модель на Sonnet

На приёмке US-04 содержание писем **не прошло** на Claude Haiku 4.5 ни в одной из трёх попыток улучшения и **прошло без замечаний** на Claude Sonnet 5.5 — ни одного утверждения сверх резюме, числа дословно, без штампов. Модель по умолчанию не меняли (ждём новую Haiku — бэклог, п. 16), но для важного отклика `cv_processing` можно разово переключить.

| | Haiku 4.5 (по умолчанию) | Sonnet 5.5 |
|---|---|---|
| Стоимость письма | ~$0,01 | ~$0,04 |
| Время | 10–12 сек | 20–24 сек |
| Вычитка | Обязательна, с правками | Обязательна, правок обычно мало |

**Когда стоит:** вакансия, в которую вы действительно хотите попасть, или письмо Haiku проще переписать, чем поправить.

**Способ 1 — правка профиля** ([что такое профиль](configuration.md#Что%20такое%20профиль)). В `profile/preferences.json`, блок `llm_preferences` → `llm_providers`:

```json
"cv_processing": {"provider": "anthropic", "model": "claude-sonnet-5-5"}
```

Сгенерировать письмо (и при желании `cv-tips` по той же вакансии), затем вернуть `claude-haiku-4-5`. Пока стоит Sonnet, на него же уйдёт и сравнение с резюме в `analyze` — смена модели сбрасывает кэш сравнения, и оно пересчитается.

**Способ 2 — без правки профиля**, через скрипт сравнения моделей.

Синтаксис:

```
.venv\Scripts\python.exe -m scripts.eval_cover_letters --model <модель> [--provider <провайдер>] [--vacancy <vacancy_id>]… [--prompt <файл>] [--tone <тон>] [--plan]
```

| Параметр | Что задаёт | Значения и где взять |
|---|---|---|
| `--model <модель>` | Модель, на которой писать письма (**обязательный**) | Идентификатор модели провайдера: `claude-sonnet-5-5`, `claude-haiku-4-5`; для других провайдеров — см. [Настройки](configuration.md) и [подключение DeepSeek и Qwen](deepseek-qwen-setup.md) |
| `--provider <провайдер>` | Провайдер модели | `anthropic` (по умолчанию), `deepseek`, `qwen`, `ollama` |
| `--vacancy <vacancy_id>` | Для каких вакансий писать; можно повторить | ID вакансии — число из ссылки `hh.ru/vacancy/<ID>`. Без параметра — три вакансии набора приёмки US-04 |
| `--prompt <файл>` | Вариант промпта вместо `prompts/cover_letter.md` — для экспериментов | Путь к `.md`-файлу промпта, например из `prompts/experiments/` |
| `--tone <тон>` | Тон письма вместо `tone` из профиля | `professional`, `professional_and_enthusiastic`, `friendly`, `formal` или своё описание |
| `--plan` | Флаг без значения: модель дополнительно объясняет, на какую цитату опирается каждый абзац | — |

Пример — письмо на Sonnet по одной вакансии:

```powershell
.venv\Scripts\python.exe -m scripts.eval_cover_letters --model claude-sonnet-5-5 --vacancy 137587921
```

Письмо сохраняется не в `reports/cover_letters/`, а в `reports/eval/claude-sonnet-5-5-<дата-время>/`; в конце выводится сводка (слова, найденные цитаты, требования без подтверждения). Для `cv-tips` такого скрипта пока нет (бэклог, п. 16) — только способ 1.

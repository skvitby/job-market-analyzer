# Анализ рынка (`analyze`)

[← к оглавлению](index.md)

## Зачем

Ответить на два вопроса: **какие навыки чаще всего требует рынок** и **какие из них есть в моём резюме, а каких нет**. Результат — план правок резюме (что вынести в «Навыки») и план обучения (реальные пробелы).

## Запуск

**Синтаксис:**

```
.venv\Scripts\python.exe -m src.cli analyze [--data <файл>] [--days <N>] [--area <город>] [--no-llm] [--llm-refresh]
```

Все параметры необязательны, без них анализируются все накопленные вакансии. Значения — в таблице «Опции» ниже.

**Примеры:**

```powershell
.venv\Scripts\python.exe -m src.cli analyze                      # все накопленные вакансии
.venv\Scripts\python.exe -m src.cli analyze --area Минск         # только Минск
.venv\Scripts\python.exe -m src.cli analyze --area Минск --days 7
.venv\Scripts\python.exe -m src.cli analyze --no-llm             # только словарь, без LLM
```

## Опции

| Параметр | Что делает | Значения и формат | Где взять / по умолчанию | Пример |
|---|---|---|---|---|
| `--data <файл>` | Анализировать один файл выгрузки вместо всех | Путь к файлу — от корня проекта или полный | Файлы — в папке `data/`, имя содержит дату и время выгрузки: `raw_vacancies_ГГГГММДД_ЧЧММСС.json`. По умолчанию объединяются все `data/raw_vacancies_*.json` без дублей (при повторе берётся запись из самого свежего файла) | `--data data\raw_vacancies_20260926_150205.json` |
| `--days <N>` | Только вакансии, опубликованные **или поднятые работодателем** за последние N дней — т.е. активные, а не только новые | Целое число от 1 | По умолчанию — без ограничения по дате | `--days 7` |
| `--area <город>` | Только вакансии одного города | **Название города, как в вакансиях HH**, а не ID региона (в отличие от `fetch --region`) и не название страны. Регистр не важен; с пробелами — в кавычках | Как город написан на странице вакансии hh.ru или в поле `area` файлов `data/raw_vacancies_*.json`. Если название не найдено, команда сама выведет до 10 городов, которые есть в данных. По умолчанию — все города | `--area Минск`, `--area "Нижний Новгород"` |
| `--no-llm` | Флаг без значения: только точный поиск по словарю — без навыков вне словаря и без сравнения с резюме. Не обращается к LLM, бесплатно | — | По умолчанию LLM используется | `--no-llm` |
| `--llm-refresh` | Флаг без значения: заново отправить в LLM вакансии, уже обработанные раньше, — текущей моделью задачи `vacancy_analysis` (модель для анализа вакансий из профиля; см. [задачи LLM](index.md#Основные%20термины)) (платно) | — | По умолчанию в LLM уходят только новые вакансии | `--llm-refresh` |

Если город не найден, команда подскажет, какие города есть в данных. Применённые фильтры записываются в шапку отчёта.

## Как получается отчёт

```
вакансии из data/ (+ фильтры --days / --area)
   ↓
1. Точный поиск по словарю — в полном описании из data/details/ (если нет — в сниппетах) и в key_skills
2. LLM (vacancy_analysis) — навыки вне словаря, только по вакансиям с полным описанием
3. Сравнение с резюме — навыки словаря точным поиском, навыки вне словаря через LLM (cv_processing)
   ↓
reports/market_skills_summary.md
```

Отчёт каждый раз перезаписывается целиком. Если нужно сохранить прежнюю версию (например, для сравнения во времени), скопируйте файл до запуска.

## Как читать отчёт

### Шапка

Время формирования, источник (сколько выгрузок и за какие даты), фильтры, период публикации вакансий (с учётом поднятий), число вакансий и **сколько из них по полному описанию, а сколько по сниппетам**.

Если в профиле задан `professional_roles`, роли перечислены в строке «Фильтры», а строка «Фильтр ролей HH» показывает, сколько вакансий исключено (сохранённые роли не входят в список) и сколько проанализировано без сведений о роли — это вакансии из выгрузок до 08.10.2026, они анализируются как есть ([Роли HH](configuration.md#Роли%20HH)).

> [!warning] Вакансии без полного описания
> Если в шапке есть «по сниппетам» больше нуля и предупреждение «N вакансий без полного описания» — частоты навыков занижены: в сниппетах часть требований обрезана. Догрузите описания обычным `fetch` (без `--no-details`).

### Разделы

| Раздел | Что показывает | Как использовать |
|---|---|---|
| **Топ навыков** | Навыки словаря: в скольких вакансиях встретились и доля. Навык считается не более одного раза на вакансию | Главная картина рынка. Точный поиск — результаты стабильны между запусками |
| **Не встретились ни в одной вакансии** | Навыки словаря с нулевой частотой | Кандидаты на удаление из словаря или признак неудачного синонима |
| **key_skills HH вне словаря** (топ-20) | Теги «Ключевые навыки», которые работодатели указали на HH, но словарь их не знает | Кандидаты на пополнение словаря |
| **Навыки вне словаря, найденные LLM** (топ-30) | Что модель нашла в описаниях сверх словаря; указана модель и сколько вакансий обработано | Интерпретация модели, а не точный поиск: формулировки одного навыка могут дублироваться (`Word` / `MS Word`). Частые — добавить в словарь |
| **Сравнение с резюме** | Статус каждого востребованного навыка в вашем резюме | План правок резюме и обучения — см. ниже |
| **Файлы выгрузок** (свёрнут) | Каждый файл выгрузки: время, регионы, вакансий в файле и сколько вошло в отчёт | Проверить, откуда взялись цифры |

С `--no-llm` разделов про LLM и сравнения с резюме нет. С `--data` нет блока «Файлы выгрузок».

### Сравнение с резюме

**Какие навыки попадают:** из словаря — встречающиеся не менее чем в 5% вакансий; найденные LLM — не менее чем в 2 вакансиях (помечены `*`).

| Статус | Значит | Что делать |
|---|---|---|
| ✅ Matches | Навык есть в разделе «Навыки» резюме | Ничего |
| 🟡 Добавить в «Навыки» | Навык упомянут в опыте, но не в разделе «Навыки» | Вынести в раздел «Навыки»: HR и ATS смотрят в первую очередь его |
| ⚠️ Gap to address | Навыка в резюме нет | Если опыт есть — дописать в резюме своими словами. Если нет — в план обучения или подготовки к интервью |

Колонка «Где в резюме» — фрагмент резюме, подтверждающий статус.

**Итог раздела** — сколько навыков в каждом статусе и **покрытие рынка** резюме с учётом частоты навыков: навык, который требуют в 50% вакансий, весит больше, чем навык из 5%.

**Насколько можно доверять статусам:**

- **Навыки словаря** — только точный поиск по резюме с синонимами. Статус стабилен и не зависит от модели. Ложный ⚠️ почти всегда означает, что в резюме навык назван иначе, чем в словаре: добавьте синоним в словарь или формулировку в резюме.
- **Навыки `*`** — по ответу LLM. Совпадение засчитывается, только если цитата модели есть в резюме **и** содержит слово из названия навыка; иначе навык считается отсутствующим. Статусы `*` могут немного меняться от запуска к запуску. Если навык `*` важен — добавьте его в словарь, и он перейдёт в точный поиск.
- В сноске раздела указано, сколько ответов LLM по навыкам `*` проверка не засчитала или понизила.

> [!tip] Как работать с разделом
> Пройдите таблицу построчно, как в приёмке US-03 (TC-14 [протокола](../testing/test-report-us01-03.md)): сначала 🟡 — это быстрые правки резюме; затем ⚠️ — разделить на «опыт есть, но не описан» и «реальный пробел». После правки резюме просто запустите `analyze` снова — сравнение пересчитается автоматически.

## Кэши и повторные запуски

| Кэш | Что хранит | Когда обращается к LLM снова |
|---|---|---|
| `data/llm_skills_cache.json` | Навыки вне словаря по каждой вакансии: навыки, провайдер, модель, дата | Только для вакансий, которых ещё нет в кэше. `--llm-refresh` — заново все отфильтрованные |
| `data/cv_match_cache.json` | Последний ответ LLM по сравнению с резюме + отпечаток: резюме, список навыков, модель | Если изменилось резюме, список навыков для сравнения (другие фильтры, правка словаря) или модель `cv_processing` |

Что из этого следует:

- Повторный `analyze` на тех же данных — без запросов к LLM и за секунду.
- После `fetch` в LLM уходят только новые вакансии.
- Кэш сравнения хранит **только последний** результат: при чередовании фильтров (`--area Минск`, затем без него, затем снова с ним) сравнение с резюме каждый раз пересчитывается — около цента за раз (бэклог, п. 11).
- `--llm-refresh` перезаписывает результаты прежней модели. Если хотите сравнить модели — сначала скопируйте `data/llm_skills_cache.json` (см. [подключение DeepSeek и Qwen](deepseek-qwen-setup.md), раздел 4.3).
- Повреждённый файл кэша LLM программа не чинит, а начинает заново (предупреждение `Повреждён кэш LLM …, начинаю заново`) — вакансии будут отправлены в LLM повторно.

## Если LLM недоступна

Отчёт всё равно строится:

- сбой на этапе вакансий — отчёт по словарю и тому, что уже есть в кэше LLM; в разделе LLM — `Обработка LLM прервана: …`, в терминале — `Внимание: LLM-анализ вакансий прерван: …`. Полученные до сбоя результаты сохранены;
- сбой при сравнении с резюме — в разделе «Сравнение с резюме» и в терминале `Сравнение с резюме не выполнено: …`;
- нет файла резюме — в разделе «Сравнение с резюме»: `Файл резюме profile/my_cv.md не найден — сравнение пропущено.`

В этих случаях команда завершается успешно (код 0) — смотрите на жёлтые строки `Внимание:` в терминале. Причины ошибок — в [Частых проблемах](troubleshooting.md#LLM).

## Стоимость

На Claude Haiku 4.5: 48 вакансий Минска первый раз — около $0,07; дальше — только новые вакансии и пересчёт сравнения с резюме (~$0,01). Подробнее — [Стоимость](costs.md).

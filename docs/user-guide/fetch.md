# Сбор вакансий (`fetch`)

[← к оглавлению](index.md)

## Зачем

Собрать локальную базу вакансий BA/SA с HH.ru, на которой работают все остальные команды. `analyze` работает только по локальным данным (офлайн), `cover-letter` и `cv-tips` берут из неё описание и метаданные вакансии.

## Запуск

```powershell
.venv\Scripts\python.exe -m src.cli fetch                                  # по настройкам профиля
.venv\Scripts\python.exe -m src.cli fetch --region 16                      # только Беларусь
.venv\Scripts\python.exe -m src.cli fetch --region 16 --schedule remote    # разово переопределить профиль
.venv\Scripts\python.exe -m src.cli fetch --region 16 --no-details         # быстро, без полных описаний
```

## Опции

Все опции необязательны и переопределяют `search_settings` из `profile/preferences.json` только на этот запуск ([Настройки](configuration.md)).

| Опция | Что задаёт | Пример |
|---|---|---|
| `--role` | Роль для поиска по названию вакансии | `--role "Системный аналитик"` |
| `--region` | ID региона HH (не название): 113 — Россия, 16 — Беларусь | `--region 16` |
| `--experience` | `noExperience` / `between1And3` / `between3And6` / `moreThan6` | `--experience between3And6` |
| `--employment` | `full` / `part` / `project` | `--employment project` |
| `--schedule` | `office` / `hybrid` / `remote` | `--schedule remote --schedule hybrid` |
| `--min-salary` | Минимальная зарплата (валюта — `currency` из профиля); отсекает вакансии без зарплаты | `--min-salary 3000` |
| `--no-details` | Не загружать полные описания в `data/details/` | — |

Несколько значений одной опции — повтором опции: `--region 113 --region 16`. Значения с пробелами — в кавычках. Опция **заменяет** соответствующий список профиля целиком: `--role "Системный аналитик"` ищет только эту роль.

## Как работает

**1. Поиск.** Роли объединяются в один запрос через OR, поиск идёт только по названию вакансии, слова из `exclude_words` исключаются. Результаты без дублей по `id`. HH отдаёт не больше 2000 вакансий на один поиск: если найдено больше, запрос автоматически дробится по регионам, затем по уровням опыта. Если и этого мало — предупреждение `HH отдаёт только первые 2000. Сузьте фильтры.`

**2. Инкрементальная глубина поиска.** Программа сама решает, за какой период искать:

| Ситуация | Период поиска |
|---|---|
| По одному из запрошенных регионов выгрузок ещё не было | За `initial_period_days` дней (по умолчанию 14) |
| По всем регионам выгрузки уже были | С самой ранней из последних выгрузок по этим регионам, с запасом 1 час |
| Прошлая выгрузка была больше 30 дней назад | За 30 дней — глубже HH не отдаёт; в логе предупреждение |

Время последней выгрузки считается **по каждому региону отдельно**. Поэтому можно чередовать `fetch --region 16` и полный `fetch` — вакансии других регионов не потеряются. Пропуск нескольких дней тоже не страшен: следующий запуск догрузит всё с момента прошлой выгрузки.

**3. Новые и известные вакансии.** Выгрузка сообщает, сколько вакансий **новых** (их `id` нет в прежних выгрузках) и сколько уже известных. Известные — это вакансии, поднятые работодателем (HH при этом обновляет дату публикации), или попавшие в запас 1 час.

**4. Полные описания.** Поиск HH отдаёт только короткие сниппеты требований и обязанностей (~330 символов, часто обрезаны). Поэтому после поиска для каждой вакансии, которой ещё нет в кэше, запрашивается полное описание и `key_skills` — отдельным запросом с паузой `request_delay_sec` ([ADR-002](../adr/002-vacancy-details-cache.md)).

- Берутся вакансии **из всех выгрузок**, а не только из текущей: то, что не загрузилось раньше, догрузится сейчас.
- С `--region` описания загружаются только для вакансий этих регионов, включая их области и города (список — из справочника HH); без `--region` — для всех.
- Уже загруженные описания повторно не запрашиваются.
- Ошибка по одной вакансии не прерывает загрузку; после 5 ошибок подряд этап останавливается, остальное догрузится при следующем `fetch`.
- Вакансия удалена с HH (404) — сохраняется в кэш без описания и больше не запрашивается.
- Каждое описание сохраняется сразу: загрузку можно прервать Ctrl+C без потери уже скачанного.

> [!note] Сколько это занимает
> Одно описание — один запрос с паузой 3 сек. Первая загрузка ~900 вакансий РФ + РБ — около 45 минут, последующие — только новые вакансии. Перед загрузкой в логе — оценка времени, по ходу — прогресс каждые 10 вакансий.

## Что выводит

Пример по протоколу приёмки US-01…03 (время в начале строк лога заменено на «…»):

```
… Первая выгрузка для регионов 16: ищу вакансии за последние 14 дн.
   или: Ищу вакансии с 26.09 14:07 (последние выгрузки по регионам: 16 — 26.09 15:07)
… Страница 1/1, всего найдено 22
… Результат поиска: 22 вакансии — новых 5, уже известных 17 (есть в прошлых выгрузках)
Готово: 22 вакансии (новых 5) → …\data\raw_vacancies_20260926_150205.json
… Описания только для регионов 16: 281 населённый пункт в справочнике HH
… Загружаю полные описания: 7 вакансий (меньше минуты)
… Описания: 7/7 (готово)
Описания: загружено 7, ошибок 0
```

Строка `Описания: …` жёлтая, если были ошибки. Если все описания уже в кэше — `Все описания вакансий уже в кэше`.

## Какие файлы создаёт

| Файл | Что внутри |
|---|---|
| `data/raw_vacancies_{ГГГГММДД_ЧЧММСС}.json` | Снимок одного поиска: время выгрузки, период / дата начала поиска, параметры запроса, число вакансий и новых, сами вакансии: `id`, `name`, `salary`, `area` (город), `employer`, `requirement`, `responsibility`, `alternate_url`, `published_at` |
| `data/details/{id}.json` | Кэш полного описания: `description` (абзацы в Markdown), `key_skills`, `fetched_at` |

Снимки выгрузок не меняются задним числом; при 0 найденных вакансий файл всё равно создаётся — он фиксирует время поиска по региону. Папка `data/` не хранится в git: на другом компьютере базу нужно собрать заново.

> [!tip] Практика
> - Регулярный запуск `fetch --region 16` раз в несколько дней держит базу Беларуси свежей за секунды-минуты.
> - `--no-details` полезен, когда нужен только список вакансий; описания догрузятся следующим обычным `fetch`.
> - Если HH не отвечает или блокирует запросы — см. [Частые проблемы](troubleshooting.md#HH%20и%20сеть).

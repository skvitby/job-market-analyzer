# Частые проблемы

[← к оглавлению](index.md)

Как устроены сообщения:

- **`Ошибка: …`** (красным) — команда остановлена, код выхода 1. Файлы результата не созданы.
- **`Внимание: …`** (жёлтым) — результат сохранён, но что-то нужно проверить.
- Строки лога со временем в начале — ход работы; среди них бывают предупреждения (повторы запросов, пропущенные файлы).

Ниже — реальные тексты сообщений из кода. `…` — подставляемые значения.

## HH и сеть

| Сообщение | Причина | Что делать |
|---|---|---|
| `В .env не задан HH_APP_TOKEN (токен приложения HH)` | Нет токена в `.env` | Получить токен приложения ([Установка](getting-started.md), раздел 2) |
| `В .env не задан HH_USER_AGENT` | Нет User-Agent | Заполнить: `AppName/1.0 (your_email@example.com)` |
| `curl не найден: укажите путь в HH_CURL_PATH в .env` | `HH_CURL_PATH` пуст, а `curl` нет в PATH | Указать полный путь к `curl.exe` |
| `HH заблокировал IP (DDoS-Guard): проверьте, что curl исключён из VPN` | Запрос к HH ушёл через VPN | Проверить исключение `curl` в VPN-клиенте и что `HH_CURL_PATH` указывает именно на исключённый `curl.exe` |
| `curl завершился с кодом N: нет соединения с api.hh.ru` | Сетевой сбой (после 3 повторов) | Проверить интернет; повторить позже |
| `HH вернул 403: проверьте HH_APP_TOKEN` | Токен неверный или отозван | Проверить токен в `.env`, при необходимости получить новый |
| `HH ответил 429 (curl=0), повтор 1/3 через 10 сек` (лог) | HH ограничивает частоту запросов | Ничего: программа сама повторит с паузой 10, 20, 30 сек |
| `HH вернул HTTP 429: …` / `HH вернул HTTP 503: …` | Повторы не помогли | Подождать; можно увеличить `request_delay_sec` в профиле |
| `По запросу найдено: N вакансий, HH отдаёт только первые 2000. Сузьте фильтры.` (лог) | Даже после разбиения по регионам и опыту результатов больше лимита HH | Сузить фильтры: регион, роли, формат работы |
| `Прошлая выгрузка была более 30 дней назад: вакансии старше … HH уже не отдаёт` (лог) | Долгий перерыв между выгрузками | Ничего: выгрузятся вакансии за 30 дней; более старые недоступны |
| `5 ошибок подряд — останавливаю загрузку описаний, оставшиеся загрузятся при следующем fetch` (лог) | Серия ошибок при загрузке описаний — обычно сеть или блокировка | Разобраться по тексту ошибок выше в логе, затем снова `fetch` |
| `Вакансия N удалена с HH, сохраняю без описания` (лог) | Вакансия закрыта | Ничего: больше не будет запрашиваться |
| `Описания: загружено N, ошибок M` (жёлтым) | Часть описаний не загрузилась | Следующий `fetch` догрузит их автоматически |

> [!tip] VPN нельзя выключить
> Отключать VPN целиком не нужно: к HH ходит только `curl` из `HH_CURL_PATH`, остальное (включая LLM) остаётся в VPN. Схема — [Установка](getting-started.md), раздел 3.

## Настройки

| Сообщение | Причина | Что делать |
|---|---|---|
| `Некорректный JSON в файле …: …` | Синтаксическая ошибка в `preferences.json` | Исправить по указанной строке и позиции (часто — лишняя/пропущенная запятая) |
| `Файл … должен содержать JSON-объект верхнего уровня` | Файл — не объект `{…}` | Вернуть структуру `{ "search_settings": …, … }` |
| `Файл … не найден, используются значения по умолчанию` (лог) | Нет `profile/preferences.json` | Если так и задумано — ничего; иначе восстановить файл |
| `Неизвестные значения schedule: […]. Допустимые: ['office', 'hybrid', 'remote']` (так же для `employment_type`) | Опечатка в значении | Исправить в профиле или в опции `fetch` |
| `Неизвестные значения experience_level: […]` | Опечатка | Допустимо: `noExperience`, `between1And3`, `between3And6`, `moreThan6` |
| `Не задан ни один target_role для поиска` | Пустой `target_roles` | Добавить роли |
| `analytical_skills_dictionary должен быть списком или объектом {навык: [синонимы]}` | Неверный формат словаря | Привести к `{"Навык": ["синоним"]}` |

## analyze

| Сообщение | Причина | Что делать |
|---|---|---|
| `В data/ нет файлов raw_vacancies_*.json — сначала выполните fetch` | Нет выгрузок | Запустить `fetch` |
| `Город «…» не найден в выгрузках. --area — название города, как в вакансиях HH, а не ID региона. Есть: …` | В `--area` передан ID или город, которого нет в данных | Взять название из подсказки: `--area Минск` |
| `После применения фильтров не осталось вакансий` | `--days` / `--area` отсекли всё | Увеличить `--days` или обновить базу `fetch` |
| `Внимание: LLM-анализ вакансий прерван: …` | Ошибка LLM на этапе вакансий | Отчёт построен по словарю и кэшу. Причина — в тексте после двоеточия, см. раздел «LLM» |
| `Внимание: Сравнение с резюме не выполнено: …` | Ошибка LLM при сравнении | То же |
| `Файл резюме profile/my_cv.md не найден — сравнение пропущено.` (в отчёте) | Нет резюме | Положить резюме в `profile/my_cv.md` |
| `LLM не вернул результат по вакансиям … — обработаются при следующем запуске` (лог) | Модель пропустила часть вакансий пакета | Ничего: следующий `analyze` отправит их снова. Если повторяется у Ollama — известная проблема малой модели (бэклог, п. 15) |
| `Сравнение с резюме: ответов LLM по навыкам вне словаря не засчитано или понижено — N …` (лог) | Цитаты модели не прошли проверку | Ничего: так работает защита от выдуманных совпадений |
| `Повреждён кэш LLM …, начинаю заново` (лог) | Файл кэша испорчен (например, ручной правкой) | Вакансии будут отправлены в LLM повторно — это стоит денег |
| `Повреждён файл кэша data/details/….json …, использую сниппет` (лог) | Испорчен файл описания | Удалить этот файл и запустить `fetch` — описание загрузится заново |

## LLM

Эти ошибки одинаковы для `analyze`, `cover-letter`, `cv-tips`. Временные сбои (429, 5xx, обрыв соединения, таймаут) программа сама повторяет до 3 раз — сообщение появляется, только если повторы не помогли.

| Сообщение | Причина | Что делать |
|---|---|---|
| `В .env не задан ANTHROPIC_API_KEY — ключ для провайдера anthropic` (или `DEEPSEEK_API_KEY`, `DASHSCOPE_API_KEY`) | Нет ключа выбранного провайдера | Добавить ключ в `.env` |
| `Ключ … недействителен или истёк — создайте новый в … и обновите .env` | Неверный или отозванный ключ; у Qwen — ключ другого региона | Создать новый ключ в консоли провайдера |
| `Закончился баланс … — пополните в …` | Нет средств на балансе | Пополнить в Anthropic Console / кабинете DeepSeek |
| `Нет соединения с … (…): проверьте интернет/VPN` | Нет доступа к провайдеру | Проверить, что VPN включён (Claude из РФ/РБ — через VPN); сменить сервер VPN |
| `Нет доступа к … / …: …` | Провайдер отказал в доступе к модели | Разобраться по тексту ответа провайдера |
| `Модель … не найдена у провайдера … — проверьте llm_providers.….model` | Опечатка в имени модели или модель недоступна | Исправить `model` в `llm_providers`. Если меняли только `provider` — укажите и `model` |
| `Превышен лимит запросов … (повторы не помогли) — попробуйте позже` | Лимит провайдера | Подождать и повторить |
| `Ответ … обрезан по лимиту токенов — уменьшите batch_size` | Ответ не поместился в лимит 8192 токенов | В `analyze` — уменьшить `batch_size` у `vacancy_analysis`. У DeepSeek и Qwen частая причина — включённый режим рассуждений (thinking), см. [подключение](deepseek-qwen-setup.md), раздел 1. В письмах и советах `batch_size` не влияет — повторить запуск |
| `… отказался отвечать на запрос` | Модель Claude отказалась отвечать | Повторить; при повторении — проверить содержимое резюме/вакансии |
| `… вернул некорректный JSON: …`, `… вернул не JSON-объект`, `В ответе … нет обязательного поля «…»`, `… поле «…» неверного типа` | Модель ответила не по схеме (чаще у DeepSeek, Qwen, Ollama) | Повторить; если систематически — сменить модель |
| `llm_providers.…: неизвестный provider «…». Допустимые: anthropic, deepseek, qwen, ollama` | Опечатка в `provider` | Исправить |
| `llm_providers.…: не задана model` | Нет поля `model` | Добавить |

### Ollama

| Сообщение | Причина | Что делать |
|---|---|---|
| `Ollama не отвечает на http://localhost:11434/v1: запустите приложение Ollama` | Ollama не запущена | Запустить приложение Ollama |
| `Модель … не скачана в Ollama — выполните: ollama pull …` | Модели нет локально | Выполнить указанную команду. `qwen3-4b-8k` — не модель из библиотеки, а локальный вариант: `ollama pull qwen3:4b-instruct-2507-q4_K_M`, затем `ollama create qwen3-4b-8k -f docs/ollama/Modelfile` |
| Первый запрос идёт очень долго | Модель загружается в память — до пары минут на слабой видеокарте | Подождать: таймаут для Ollama — 10 минут |
| Письмо или советы «потеряли» инструкцию, ответ странный | Для `cv_processing` выбрана модель с контекстом 4K — Ollama молча обрезала начало запроса | Использовать вариант с 8K (`qwen3-4b-8k`) — [Настройки](configuration.md), раздел 4.1 |

## Письма и советы

| Сообщение | Причина | Что делать |
|---|---|---|
| `Не найдено резюме profile/my_cv.md — оно нужно для письма` (`… для советов`) | Нет файла резюме | Положить резюме в `profile/my_cv.md` |
| `Некорректный ID вакансии: «…» — ожидается число, например 137798209` | Передана ссылка или текст | Передать только число из ссылки `hh.ru/vacancy/<ID>` |
| `Вакансия N не найдена на HH: удалена или неверный ID` | Вакансии нет на HH | Проверить ID; если вакансия закрыта — откликнуться уже нельзя |
| `Вакансия N удалена с HH, полного описания в кэше нет` | Вакансия закрыта до загрузки описания | Сгенерировать по ней нельзя |
| Ошибки HH (`HH заблокировал IP…`, `HH вернул 403…`) при `cover-letter` / `cv-tips` | Описания нет в кэше, и запрос к HH не прошёл | См. раздел «HH и сеть» или сначала выгрузить вакансию через `fetch` |
| `Не найден файл промпта prompts/…` | Файл промпта удалён или переименован | Восстановить из git |
| `Плейсхолдеры в prompts/… не совпадают с ожидаемыми — неизвестные: …; нет в файле: …` | При правке промпта удалён или искажён плейсхолдер, либо в тексте появились `{слово}` | Вернуть плейсхолдеры, убрать лишние фигурные скобки — [Настройки](configuration.md), раздел 5 |
| `llm_preferences.cover_letter_language: неизвестное значение «…». Допустимые: ru, en, auto` | Опечатка | Исправить в профиле |
| `… вернул пустое письмо — попробуйте ещё раз` | Модель вернула пустой текст | Повторить запуск |

Предупреждения `Внимание:` о найденных/ненайденных цитатах, числах, терминах и пробелах — не ошибки, а результат проверок кодом. Как их читать — [cover-letter](cover-letter.md#Сообщения%20в%20терминале) и [cv-tips](cv-tips.md).

## Кодировка вывода

**Симптом:** кириллица в терминале превращается в «кракозябры» или команда падает с `UnicodeEncodeError` на символе «→».

Для `python -m src.cli …` это исправлено: при выводе не в окно консоли (через `!` в Claude Code, с перенаправлением, по расписанию) CLI сам переключает вывод на UTF-8. Если симптом появился у команд `src.cli` — это дефект, стоит завести замечание.

Скрипт `scripts/eval_cover_letters.py` такого переключения не содержит. Если его вывод искажается при запуске через `!` или с перенаправлением — задать кодировку вывода Python переменной окружения перед запуском (в PowerShell: `$env:PYTHONIOENCODING = "utf-8"`).

Файлы отчётов, писем и советов всегда сохраняются в UTF-8 и корректно открываются в Obsidian.

## Команда отработала, но результат странный

| Симптом | Причина | Что делать |
|---|---|---|
| В отчёте много вакансий «по сниппетам» | Не загружены полные описания (`--no-details` или ошибки загрузки) | Запустить `fetch` без `--no-details` |
| В «Сравнении с резюме» ни один навык словаря не получил ✅, всё найденное — 🟡 | В резюме нет заголовка «Навыки» | Оформить раздел заголовком Markdown — [Настройки](configuration.md#Требования%20к%20резюме) |
| Навык, который есть в резюме, отмечен ⚠️ | В резюме он назван иначе, чем в словаре | Добавить синоним в словарь или формулировку в резюме |
| Статусы навыков `*` меняются между запусками | Недетерминированность LLM | Добавить важный навык в словарь — он перейдёт в точный поиск |
| `analyze` завершился успешно, но в отчёте нет LLM-разделов с данными | LLM-этап прерван, код выхода при этом 0 | Смотреть жёлтые строки `Внимание:` в терминале |

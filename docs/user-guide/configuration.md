# Настройки

[← к оглавлению](index.md)

## Что такое профиль

**Профиль** — это файл `profile/preferences.json` в папке проекта (US-01). В нём хранятся все настройки программы: что искать на HH, какой словарь навыков использовать, какие LLM и с какими параметрами вызывать, как писать письма. Когда в руководстве сказано «из профиля», «в профиле», «по настройкам профиля», — речь об этом файле.

Команды берут значения из профиля; опции командной строки (`fetch --region …`) переопределяют их только на один запуск, сам файл при этом не меняется.

**Где посмотреть и как открыть.** Путь: `<папка проекта>\profile\preferences.json`. Это текстовый файл в формате JSON — открывается любым текстовым редактором (Блокнот, Notepad++, VS Code). Obsidian по умолчанию показывает только Markdown-файлы, поэтому `.json` в нём не виден — открывайте редактором. Файл хранится в git, так что любую правку можно откатить.

**Из чего состоит** — четыре блока верхнего уровня:

| Блок | Что задаёт | Для каких команд | Подробно |
|---|---|---|---|
| `search_settings` | Фильтры поиска на HH: роли, регионы, опыт, занятость, формат работы, зарплата, стоп-слова, глубина выгрузки | `fetch` | Раздел 1 ниже |
| `analytical_skills_dictionary` | Словарь навыков с синонимами — по нему точным поиском считаются навыки в вакансиях и в резюме | `analyze`, `cover-letter`, `cv-tips` (проверки) | Раздел 2 |
| `excluded_skills` | Навыки, которые не нужно показывать в отчёте (например, 1С) | `analyze` | Раздел 3 |
| `llm_preferences` | LLM-провайдер и модель для каждой задачи (`llm_providers`), язык, тон, акценты и объём писем | `analyze`, `cover-letter`, `cv-tips` | Раздел 4 |

Сокращённо структура выглядит так:

```json
{
  "search_settings": { "target_roles": ["Бизнес-аналитик", "…"], "regions": [{"id": 16, "name": "Беларусь"}], "…": "…" },
  "analytical_skills_dictionary": { "SQL": [], "REST API": ["REST", "RESTful"], "…": [] },
  "excluded_skills": ["1С", "SAP"],
  "llm_preferences": {
    "cover_letter_language": "auto", "tone": "…", "focus_areas": ["…"], "cover_letter_max_words": 250,
    "llm_providers": {
      "vacancy_analysis": {"provider": "anthropic", "model": "claude-haiku-4-5"},
      "cv_processing":    {"provider": "anthropic", "model": "claude-haiku-4-5"}
    }
  }
}
```

Колонка «Сейчас в профиле» в таблицах ниже — значения из файла на момент написания руководства; актуальные — в самом файле.

**Как работают значения по умолчанию** (`src/config.py`):

- нет файла — работают значения по умолчанию, в логе предупреждение `Файл … не найден, используются значения по умолчанию`;
- нет поля — берётся значение по умолчанию для этого поля; блоки-объекты (`search_settings`, `llm_preferences`, `llm_providers`) дополняются поле за полем;
- **списки и словарь навыков заменяются целиком**: если задать `analytical_skills_dictionary`, словарь по умолчанию не используется вовсе;
- битый JSON — команда останавливается: `Некорректный JSON в файле … ` с позицией ошибки.

> [!tip] Правка файла
> Файл редактируется вручную в любом редакторе. После правки достаточно перезапустить команду. Частая ошибка — лишняя или пропущенная запятая: программа покажет строку и позицию.

## 1. `search_settings` — фильтры поиска на HH (US-02)

| Поле | Что задаёт | По умолчанию в коде | Сейчас в профиле |
|---|---|---|---|
| `target_roles` | Ключевые слова поиска **по названию вакансии**; все роли объединяются через OR | Бизнес-аналитик, Системный аналитик, Business Analyst, Systems Analyst | + System Analyst, IT-аналитик, IT Analyst, Аналитик требований, Requirements Analyst, Функциональный аналитик, Functional Analyst |
| `regions` | Регионы HH: `[{"id": 113, "name": "Россия"}, …]`. `id` — ID региона HH, `name` — для удобства чтения | Россия (113), Беларусь (16) | Россия, Беларусь |
| `experience_level` | Опыт: `noExperience`, `between1And3`, `between3And6`, `moreThan6` — одно значение или список | не задан (любой) | 1–3, 3–6, 6+ лет |
| `employment_type` | Занятость: `full`, `part`, `project` — строка или список | не задан | `full` |
| `schedule` | Формат работы: `office`, `hybrid`, `remote` — список | не задан | все три |
| `min_salary` | Минимальная зарплата | `null` | `null` |
| `currency` | Валюта для `min_salary` | не задана | `RUR` |
| `exclude_words` | Слова, исключаемые из поиска через NOT (по названию вакансии) | `[]` | `["1С"]` |
| `initial_period_days` | Глубина первой выгрузки, дней (максимум HH — 30) | 14 | 14 |
| `request_delay_sec` | Пауза между запросами к HH, сек (NFR-1) | 3 | 3 |

> [!warning] `min_salary` отсекает вакансии без зарплаты
> Если `min_salary` задан, в запрос к HH добавляется «только с указанной зарплатой» — вакансии, где зарплата не указана, в выгрузку не попадут.

- Неизвестное значение в `experience_level`, `employment_type`, `schedule` — ошибка со списком допустимых значений.
- `exclude_words` убирает **вакансии** по названию. Чтобы вакансии остались, а навык не показывался в отчёте, — `excluded_skills` (раздел 3).

## 2. `analytical_skills_dictionary` — словарь навыков (US-03)

Словарь — основа точного поиска: по нему считаются частоты навыков в отчёте `analyze`, статусы навыков в резюме, отметки ⚠️ / ℹ️ в письмах и советах.

Формат — `{навык: [синонимы]}`; допустим и простой список навыков без синонимов. Навык и все его синонимы считаются одним навыком, не более одного раза на вакансию.

```json
"REST API": ["REST", "RESTful"],
"ТЗ": ["техническ задани"],
"Kafka": ["Кафк"]
```

**Как ищутся термины (AC 1.2):**

| Термин | Правило | Пример |
|---|---|---|
| Английский | Целым словом | `Git` не находится внутри `GitLab` |
| Русский | По основе: после слова допускаются любые русские буквы | `техническ задани` находит «технических заданий» |
| Короткая русская аббревиатура (до 3 заглавных букв) | Целым словом | `ПСИ` не находится в «психология» |
| Из нескольких слов | Слова могут разделяться пробелом, дефисом или ничем | `REST API` = `REST-API` |

Регистр букв не важен.

> [!tip] Как пополнять словарь
> Кандидаты — в отчёте `analyze`: разделы «key_skills HH вне словаря» и «Навыки вне словаря, найденные LLM». Частый навык оттуда стоит добавить в словарь с синонимами: он перейдёт в точный поиск и получит стабильный статус в сравнении с резюме. Для русских синонимов пишите основу слова без окончания (`интеграци`, `реляционн`).

Сейчас в профиле 88 навыков. По умолчанию в коде — 10: SQL, UML, BPMN, REST API, JSON, Swagger, Postman, Python, Agile, Scrum.

## 3. `excluded_skills` — навыки, которые не нужно показывать

Список навыков, не целевых для вас (сейчас `["1С", "1C", "SAP"]`, по умолчанию пусто). Ищутся так же, как навыки словаря: `"1С"` отсекает и «1С программирование», `"SAP"` — и «SAP BW». Не показываются ни в одном разделе отчёта и не участвуют в сравнении с резюме. Сами вакансии при этом остаются в анализе.

## 4. `llm_preferences` — LLM и письма

### 4.1. `llm_providers` — какая модель для какой задачи

Модель задаётся отдельно для двух задач (AC 1.5, [ADR-001](../adr/001-llm-provider.md)):

| Задача | Где используется | Какие данные уходят в модель |
|---|---|---|
| `vacancy_analysis` | `analyze`: навыки вне словаря в описаниях вакансий | Только публичные тексты вакансий |
| `cv_processing` | `analyze` (сравнение с резюме), `cover-letter`, `cv-tips` | **Резюме** + вакансия |

По умолчанию обе — `{"provider": "anthropic", "model": "claude-haiku-4-5"}`.

Поля одной задачи:

| Поле | Обязательно | Что это |
|---|---|---|
| `provider` | да | `anthropic`, `deepseek`, `qwen` или `ollama` |
| `model` | да | Имя модели у провайдера |
| `base_url` | нет | Другой адрес сервера провайдера |
| `batch_size` | нет | Сколько вакансий отправлять в одном запросе — **только для `vacancy_analysis`** |

| `provider` | Ключ в `.env` | Адрес по умолчанию | `batch_size` по умолчанию |
|---|---|---|---|
| `anthropic` | `ANTHROPIC_API_KEY` | — | 10 |
| `deepseek` | `DEEPSEEK_API_KEY` | `https://api.deepseek.com` | 10 |
| `qwen` | `DASHSCOPE_API_KEY` | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1` | 10 |
| `ollama` | не нужен | `http://localhost:11434/v1` | 1 |

> [!warning] Указывайте `provider` и `model` вместе
> Настройки задачи дополняют значения по умолчанию поле за полем. Если сменить только `provider`, останется `model: claude-haiku-4-5` — и провайдер ответит, что модель не найдена.

**Типовые конфигурации:**

| Цель | `vacancy_analysis` | `cv_processing` |
|---|---|---|
| По умолчанию | `anthropic` / `claude-haiku-4-5` | `anthropic` / `claude-haiku-4-5` |
| Дешевле анализ рынка | `qwen` / `qwen3.8-flash` или `deepseek` / `deepseek-flash` — см. [подключение](deepseek-qwen-setup.md) | `anthropic` / `claude-haiku-4-5` |
| Важный отклик — качественнее письмо и советы | без изменений | `anthropic` / `claude-sonnet-5-5` (разово, см. [cover-letter](cover-letter.md#Когда%20переключать%20модель%20на%20Sonnet)) |
| Бесплатно и офлайн | `ollama` / `qwen3:4b-instruct-2507-q4_K_M` | `ollama` / `qwen3-4b-8k` |

> [!note] Ollama
> - Модель должна быть скачана (`ollama pull <модель>`, где `<модель>` — имя модели из библиотеки Ollama, то же, что в поле `model`; например `ollama pull qwen3:4b-instruct-2507-q4_K_M`), а приложение Ollama — запущено.
> - Для `cv_processing` нужен вариант модели с контекстом 8K: запрос письма (~4,4K токенов) не помещается в стандартные 4K, и Ollama молча обрезает начало запроса вместе с инструкцией. Создание: `ollama create qwen3-4b-8k -f docs/ollama/Modelfile`.
> - Качество малой модели заметно ниже: в письмах она пересказывает цитаты и ломает грамматику, в `analyze` может исказить ID вакансии, и такая вакансия не обрабатывается (бэклог, п. 15). Это резервный вариант, а не основной.

Резюме уходит **только** провайдеру `cv_processing` (NFR-2). Выбирая провайдера для этой задачи, учитывайте, где он обрабатывает данные ([ADR-001](../adr/001-llm-provider.md), раздел 3).

### 4.2. Настройки сопроводительного письма

| Поле | Значения | По умолчанию в коде | Сейчас в профиле |
|---|---|---|---|
| `cover_letter_language` | `ru`, `en`, `auto` — по языку вакансии: английский, если латинских букв в описании больше, чем кириллических | `ru` | `auto` |
| `tone` | `professional`, `professional_and_enthusiastic`, `friendly`, `formal`; любое другое значение передаётся модели как есть | `professional` | `professional_and_enthusiastic` |
| `focus_areas` | Направления опыта, на которых делать акцент, — если они относятся к вакансии и подтверждаются резюме | `[]` («не заданы») | Интеграции и API; Проектирование баз данных; Сбор и документирование требований |
| `cover_letter_max_words` | Ориентир объёма письма, слов. Жёсткой обрезки нет; превышение более чем на 20% — предупреждение | 250 | 250 |

Как значения `tone` описываются модели:

| `tone` | Описание в промпте |
|---|---|
| `professional` | профессиональный, сдержанный, без канцелярита |
| `professional_and_enthusiastic` | профессиональный, с живой заинтересованностью в задачах, но без восторженных штампов |
| `friendly` | дружелюбный и простой, но деловой |
| `formal` | официально-деловой |

У `cv-tips` своих настроек нет: язык формулировок «стало» всегда определяется по вакансии (правило `auto`), советы — на русском.

## 5. Промпты

Промпт — текстовая инструкция для модели: что сделать и по каким правилам. Промпты писем и советов лежат в файлах и правятся без изменения кода. **Плейсхолдер** — поле в фигурных скобках внутри промпта (`{language}`), вместо которого программа перед отправкой подставляет значение из профиля.

| Файл | Команда | Плейсхолдеры |
|---|---|---|
| `prompts/cover_letter.md` | `cover-letter` | `{language}`, `{tone}`, `{max_words}`, `{focus_areas}` — подставляются из `llm_preferences` |
| `prompts/cv_tips.md` | `cv-tips` | `{language}` — язык «стало» по вакансии |

Инструкции `analyze` (извлечение навыков и сравнение с резюме) пока в коде `src/analyzer.py`; перенос в `prompts/` — бэклог, п. 13.

**Как править безопасно:**

- Frontmatter файла (блок между `---`) — описание для Obsidian, в модель не уходит.
- Набор плейсхолдеров в файле должен **точно** совпадать с ожидаемым: удалили или опечатали плейсхолдер — команда остановится с ошибкой `Плейсхолдеры в prompts/… не совпадают с ожидаемыми — неизвестные: …; нет в файле: …`.
- Любое слово в фигурных скобках считается плейсхолдером, в том числе русское (`{Компания}`), — не используйте фигурные скобки в тексте промпта.
- Стоп-лист штампов письма — в конце `prompts/cover_letter.md`, пополняется там же.
- Проверять правку лучше на наборе приёмки (три вакансии, на которых проверялись письма, — см. [термины](index.md#Основные%20термины)), не меняя основной промпт: `scripts/eval_cover_letters.py --model <модель> --prompt <вариант>.md` пишет письма в `reports/eval/` (`<модель>` — идентификатор модели, например `claude-haiku-4-5`; `<вариант>.md` — путь к файлу с изменённым промптом; все параметры скрипта — в главе [cover-letter](cover-letter.md#Когда%20переключать%20модель%20на%20Sonnet)). Отклонённые варианты — в `prompts/experiments/`.

> [!note] Правки промпта у Haiku 4.5 дают мало
> По итогам приёмки US-04 разброс ответов Haiku 4.5 между запусками больше эффекта правок промпта (прогоны 3, 4A, 4B в [протоколе](../testing/test-report-us04.md)). Если письма или советы не устраивают — эффективнее сменить модель `cv_processing`, чем переписывать промпт.

## Требования к резюме

`profile/my_cv.md` — обычный Markdown. Код опирается на заголовки разделов:

- **«Навыки»** — заголовок любого уровня (`## Навыки`). По нему `analyze` отличает ✅ «в разделе «Навыки»» от 🟡 «только в опыте», а `cv-tips` — ставит отметку ℹ️ «термин уже есть в разделе».
- **«О себе» или «Обо мне»** — для отметки ℹ️ в советах к этому разделу.

Если заголовка «Навыки» нет, навыки словаря, найденные в резюме, получат только 🟡 — ✅ не будет ни у одного. Числа, сроки и формулировки опыта берутся моделью и проверками кода прямо из текста — чем точнее резюме, тем точнее проверки.

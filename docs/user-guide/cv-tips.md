# Советы по адаптации резюме (`cv-tips`)

[← к оглавлению](index.md)

## Зачем это нужно

HR и ATS-системы на первом скрининге ищут в резюме **слова из вакансии**. Опыт может быть нужный, но если он назван иначе («Документирование: SRS, ТЗ»), а в вакансии написано «спецификации требований, проектная документация», резюме может не пройти фильтр.

Команда отвечает на вопрос: **какой опыт из резюме уже подходит под эту вакансию и как назвать его её словами.** Новый опыт она не придумывает и само резюме не меняет.

## Запуск

```powershell
.venv\Scripts\python.exe -m src.cli cv-tips 137587921
```

Из строки ввода Claude Code (через `!`) команда запускается в bash — там нужны прямые слэши:

```
! .venv/Scripts/python.exe -m src.cli cv-tips 137587921
```

`137587921` — ID вакансии, число из ссылки `hh.ru/vacancy/<ID>`. Результат — файл `reports/cv_tips/cv_tips_{ID}.md`. Повторный запуск создаёт `_v2`, `_v3` …; прежние файлы не меняются (в них могли остаться ваши отметки).

## Как получается результат

```
описание вакансии + profile/my_cv.md
        ↓
LLM (cv_processing): 1) пробелы — чего в резюме нет
                     2) советы — что есть, но названо иначе
        ↓
код проверяет ответ модели по резюме (⚠️ / ℹ️)
        ↓
reports/cv_tips/cv_tips_{ID}.md
```

Модель может ошибаться и приукрашивать, поэтому код перепроверяет то, что можно проверить механически. Остальное проверяете вы.

## Что в файле, сверху вниз

### 1. Шапка

Вакансия, работодатель, ссылка, номер версии, дата, модель — чтобы потом понять, откуда файл.

### 2. Советы — главная часть

Каждый совет устроен одинаково:

| Поле | Что это | Зачем |
|---|---|---|
| **Раздел «…»** | Куда в резюме вносить правку: Опыт, Навыки или О себе | Где искать место в резюме |
| **Требование вакансии** | Цитата из вакансии | Какое слово или требование «закрывает» совет |
| **Основание в резюме** | Дословная цитата из **вашего** резюме | Реальный опыт, на котором держится совет. Без основания совета быть не может |
| **Почему** | Что это даёт на скрининге | Помогает решить, стоит ли вносить правку |
| **Стало** | Готовая формулировка (блок с кнопкой копирования) | Ею заменяете или дополняете текст резюме |

**Как читать совет:** сравните «Основание» и «Стало». «Стало» должно говорить **то же самое**, только словами вакансии: без новых инструментов, масштаба, ролей, результатов.

### 3. Отметки под советом — проверки кодом

| Отметка | Что значит | Что делать |
|---|---|---|
| ⚠️ цитата не найдена в резюме | Модель пересказала или выдумала основание | Проверить, есть ли такой опыт вообще |
| ⚠️ число не найдено в резюме | В «Стало» есть цифра (годы, %, «в N раз»), которой нет в резюме | Скорее всего, модель её придумала — убрать или исправить |
| ⚠️ термин не найден в резюме | В «Стало» есть навык из словаря (REST API, Kanban…), которого нет нигде в резюме | Модель вписала то, чего в резюме нет, — совет лучше отбросить. Если опыт на самом деле есть, сначала опишите его в резюме своими словами |
| ℹ️ термин уже есть в разделе | Термин уже стоит в том разделе, куда предлагается правка | Эта часть совета лишняя — пропустить |

### 4. Блок «Пробелы» (жёлтый)

Требования вакансии, которых в резюме нет. Советов по ним **нет намеренно**: вписывать то, чего не делали, нельзя.

- Опыт на самом деле был, просто не описан → дописать своими словами.
- Опыта нет → подготовиться к вопросу на собеседовании или внести в план обучения.
- Пометка «⚠️ возможно, есть в резюме» — модель ошиблась и отнесла к пробелам то, что в резюме есть. Такой пункт можно пропустить.

### 5. Чек-лист «Перед правкой резюме»

Три вопроса к себе. Галочки отмечаются прямо в Obsidian, когда все советы пройдены.

## Как работать с файлом

По каждому совету решите: **взять / поправить / отбросить.**

Пример — вакансия 137587921 (Лайфтех), ответ Claude Haiku 4.5:

| Совет | Решение | Почему |
|---|---|---|
| 1. Навыки: `Jira, Confluence` | **Взять частично** — добавить только Jira | ℹ️: Confluence в «Навыках» уже есть. Jira используется в работе («постановка задач в Jira»), но в списке навыков её нет |
| 2. Опыт: «Разработка спецификаций требований, проектной и технической документации (SRS, ТЗ, ТП)» | **Взять** — заменить строку «Документирование: SRS, ТЗ, ТП…» | Та же деятельность, теперь её находит поиск по словам вакансии |
| 3. Опыт: «Проектирование и описание интеграций между системами» | **Поправить** | В основании — интеграция с Moodle и передача данных; «проектирование и описание» — усиление. Честнее назвать то, что делали на самом деле |
| 4. О себе: «Опыт проектирования приложений с … архитектурой» | **Отбросить** | ℹ️: термин уже есть в «Обо мне»; «проектирования» — усиление («умею работать с … архитектурой») |

Итог: 2 правки из 4 — почти как есть.

> [!important] Главное правило
> «Стало» переносится в резюме, только если на интервью вы сможете рассказать, что стоит за каждым словом.

## Правки резюме — только вручную

Команда **не меняет** `profile/my_cv.md`: автоматическая правка — вне объёма US-05. Причины:

- модель приукрашивает (советы 3–4 в примере), и автоправка незаметно занесла бы это в резюме;
- решение «взять / поправить / отбросить» принимает человек, по каждому совету;
- настоящее резюме живёт на hh.ru, туда правки всё равно переносятся руками.

**Порядок работы:**

1. `cv-tips <ID>` → открыть файл в Obsidian.
2. Пройти советы, скопировать подходящее «Стало» кнопкой в блоке.
3. Вставить в резюме на hh.ru — для конкретного отклика.
4. В `profile/my_cv.md` переносить только то, что подходит для всех вакансий (например, Jira в «Навыки»). Иначе следующие советы и письма будут строиться на резюме, подогнанном под одну компанию.

# Типовой сценарий: от выгрузки до отклика

[← к оглавлению](index.md)

```
fetch → analyze → выбор вакансии → cv-tips → правка резюме → cover-letter → вычитка → отклик на hh.ru
                ↘ пробелы → план обучения
```

Команды — в PowerShell из корня проекта; через `!` в Claude Code — с прямыми слэшами (`.venv/Scripts/python.exe`).

## 1. Обновить базу вакансий

```powershell
.venv\Scripts\python.exe -m src.cli fetch --region 16
```

Догружает вакансии с момента прошлой выгрузки и их полные описания. Раз в несколько дней достаточно. → [fetch](fetch.md)

## 2. Посмотреть рынок и своё место на нём

```powershell
.venv\Scripts\python.exe -m src.cli analyze --area Минск
```

Открыть `reports/market_skills_summary.md` в Obsidian:

- **Топ навыков** — что сейчас требуют чаще всего.
- **Сравнение с резюме** — 🟡 (вынести в «Навыки») и ⚠️ (пробелы). Итог — покрытие рынка резюме.

Полный анализ не нужен перед каждым откликом: достаточно после заметного пополнения базы или правки резюме. Чтобы видеть только актуальные вакансии — `--days 7`. → [analyze](analyze.md)

## 3. Выбрать вакансию

Программа вакансии не ранжирует — выбор за вами. Список — в `data/raw_vacancies_*.json` (поле `alternate_url` — ссылка на hh.ru) или прямо на hh.ru. ID — число из ссылки `hh.ru/vacancy/<ID>`.

Вакансию не обязательно выгружать заранее: `cv-tips` и `cover-letter` запросят её у HH по ID.

## 4. Адаптировать резюме под вакансию

```powershell
.venv\Scripts\python.exe -m src.cli cv-tips 137587921
```

Открыть `reports/cv_tips/cv_tips_137587921.md`, по каждому совету решить **взять / поправить / отбросить**, подходящее «стало» перенести в резюме на hh.ru. → [cv-tips](cv-tips.md)

> [!important] Резюме правится только вручную
> Команда не меняет `profile/my_cv.md`. В него переносите только то, что подходит для всех вакансий (например, новый навык в «Навыки»). Правки «под одну компанию» — только в резюме на hh.ru для этого отклика, иначе следующие письма и советы будут строиться на подогнанном резюме.

## 5. Сгенерировать письмо

```powershell
.venv\Scripts\python.exe -m src.cli cover-letter 137587921
```

Если на шаге 4 вы изменили `profile/my_cv.md`, письмо учтёт новую версию. → [cover-letter](cover-letter.md)

## 6. Вычитать письмо

По правилам из главы [cover-letter](cover-letter.md#Как%20вычитывать%20письмо): таблица «На чём построено письмо» → каждое предложение против резюме → числа и стаж → намёки на пункты без подтверждения → чек-лист «Перед отправкой».

Для важной вакансии — разово сгенерировать письмо и советы на Claude Sonnet 5.5 ([как переключить](cover-letter.md#Когда%20переключать%20модель%20на%20Sonnet)).

## 7. Откликнуться

Вручную на hh.ru: выбрать резюме (с правками из шага 4), вставить текст письма. Отклики программа не отправляет и не отслеживает.

## Что делать с пробелами

Пробелы — требования, которых нет в резюме — появляются в трёх местах:

| Где | Что показывает | Масштаб |
|---|---|---|
| `analyze` → «Сравнение с резюме», ⚠️ Gap to address | Навыки, которых нет в резюме, с частотой на рынке | Весь рынок (с фильтрами) |
| `cover-letter` → «Требования вакансии без подтверждения в резюме» | Требования конкретной вакансии | Одна вакансия |
| `cv-tips` → «Пробелы: требования без подтверждения в резюме» | То же, для адаптации резюме | Одна вакансия |

**Как разобрать пробел:**

1. **Пометка «⚠️ возможно, есть в резюме»** — скорее всего ошибка модели, пропустить.
2. **Опыт на самом деле есть, но не описан** — дописать в `profile/my_cv.md` своими словами (и в резюме на hh.ru). После следующего `analyze` навык перейдёт в 🟡 или ✅.
3. **Навык в резюме назван иначе, чем в словаре** — добавить синоним в `analytical_skills_dictionary` ([Настройки](configuration.md)).
4. **Опыта нет** — в план обучения или подготовки к интервью.

**Как приоритизировать план обучения:** по частоте из `analyze` — навык, который требуют в половине вакансий, важнее редкого. Повторяющиеся пробелы из писем и советов по разным вакансиям подтверждают приоритет.

> [!tip] План обучения — в Obsidian
> Удобно вести отдельной заметкой: навык, частота на рынке (из отчёта), в каких вакансиях встречался, что изучить, как подтвердить (pet-проект, курс, кейс для портфолио). После закрытия пробела — дописать опыт в резюме и перезапустить `analyze`: покрытие рынка покажет прогресс.

Пример из текущих данных (Минск, 30.09.2026, [STATUS](../STATUS.md)): главные пробелы — API (56% вакансий), банковский домен (50%), интеграционный стек (REST, JSON, Swagger, SOAP, XML, Postman — 15–21%), Acceptance Criteria, ГОСТ 34.

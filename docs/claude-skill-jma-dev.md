# Скилл Claude Code `jma-dev`

**Скилл** — набор инструкций для Claude Code, который подключается к сессии, когда задача его касается. Скилл `jma-dev` объясняет Claude Code, как работать с этим репозиторием: где что лежит, как запускать команды, в каком порядке вносить изменения, как проверять ошибки, что обновлять в документации и что проверить перед публикацией.

Это не команда CLI проекта: в терминале `jma-dev` не работает. Скилл вызывается в чате Claude Code.

## Зачем

- **Не объяснять проект заново в каждой сессии:** Claude сам знает, что читать первым и где какой модуль.
- **Безопасность:** платные запуски (LLM), запросы к HH и команды, перезаписывающие ваши отчёты, — только с вашего согласия; секреты и резюме не попадают в git.
- **Единый процесс:** план → подтверждение → один шаг → проверка → коммит.
- **Документация не отстаёт от кода:** скилл говорит, какой документ обновить после какого изменения.

## Как вызвать

```
/jma-dev [аргумент]
```

| Параметр | Значения | По умолчанию |
|---|---|---|
| `аргумент` | `orient`, `run`, `change`, `check`, `docs`, `publish` — с какого раздела начать (расшифровка — в таблице ниже) | Без аргумента Claude сам выбирает разделы по вашей задаче |

Вызывать вручную не обязательно: Claude подключает скилл автоматически, когда задача касается кода, документов или публикации этого проекта. Ручной вызов нужен, чтобы точно запустить конкретный сценарий — например, чек-лист публикации.

## Возможности

| Аргумент | Что делает Claude | Что требует вашего подтверждения |
|---|---|---|
| `orient` | Читает `docs/STATUS.md`, `requirements.md` и нужные модули `src/`, коротко рассказывает текущее состояние | — |
| `run` | Подбирает команду CLI под задачу, объясняет, что она стоит и что перезапишет; если запускаете вы — даёт пошаговую инструкцию | Любой запуск, который платный, ходит в HH или перезаписывает отчёт |
| `change` | Находит основание в требованиях (US, AC, бэклог), предлагает план, делает изменение по одному шагу | План, каждый следующий шаг, коммит |
| `check` | Бесплатные проверки: компиляция, импорт, `--help` всех команд, корректность `preferences.json`; при ошибке — разбор по руководству и коду | Проверки на реальных данных (`analyze`, письма, `fetch`) |
| `docs` | Обновляет README, `STATUS.md` и главы руководства по правилам проекта | Изменение формулировок роли и цифр в README |
| `publish` | Проходит [чек-лист публикации](../.claude/skills/jma-dev/publish-checklist.md): секреты и личные данные, код, битые ссылки, актуальность документов, что уйдёт при push; выдаёт таблицу «пункт — результат — что исправить» | Каждое исправление, коммит и push |

Сам скилл не хранит статусы US, цифры и бэклог — каждый раз берёт их из `docs/STATUS.md` и `requirements.md`, поэтому не устаревает.

## Примеры

```
/jma-dev orient
```
Claude рассказывает, на чём остановились и какой следующий шаг, — удобно в начале новой сессии.

```
/jma-dev check
```
Прогон бесплатных проверок после правок; итог — что прошло, что упало, что не проверялось.

```
/jma-dev publish
```
Чек-лист перед отправкой в GitHub; ничего не отправляется без вашего «да».

Обычные запросы без вызова скилла тоже работают — Claude подключит его сам:

| Запрос | Что произойдёт |
|---|---|
| «Добавь в fetch опцию …» | Сверка с требованиями → план → изменение → проверки → предложение обновить `docs/user-guide/fetch.md` → коммит после проверки |
| «Почему падает cv-tips?» | Разбор по `troubleshooting.md` и коду; повторный запуск — только с вашего согласия, т.к. он платный |
| «Обнови README» | Сверка цифр и статусов со `STATUS.md` и протоколами, правки по структуре витрины |

Скилл лежит в репозитории, поэтому работает только в этом проекте и виден на GitHub. В Obsidian папка `.claude/` не отображается (Obsidian скрывает папки, начинающиеся с точки) — файлы скилла открывайте на GitHub или в редакторе.

**Как менять:** попросите Claude Code внести правку в скилл, например: «в jma-dev добавь проверку …». Правки скилла — такие же шаги, как в коде: план, подтверждение, коммит. Если правка не подхватилась в текущей сессии — начните новую.
